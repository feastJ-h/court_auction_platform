# ChatGPT 브라우저 RPA 분석 및 상품성 도구 검토

## 1. Playwright/Selenium으로 ChatGPT 웹에 파일 업로드 분석을 요청하는 방식

### 기술적으로 가능한 흐름
1. Playwright 또는 Selenium으로 사용자의 브라우저를 연다.
2. ChatGPT 웹에 로그인된 세션을 사용한다.
3. PDF/HWP 파일을 업로드한다.
4. 분석 프롬프트를 입력한다.
5. ChatGPT 응답 텍스트를 복사하거나 DOM에서 추출한다.
6. 응답을 JSON으로 파싱해 DB에 저장한다.

### 실서비스 적용 위험
- 로그인 세션, CAPTCHA, UI 변경, 업로드 제한에 매우 취약합니다.
- 공식 API가 아니므로 안정적인 SLA, 재시도, 구조화 응답 보장이 어렵습니다.
- 법원 원문 PDF/HWP에는 개인정보나 민감 정보가 포함될 수 있어, 브라우저 업로드 자동화는 감사/동의/보안 통제가 필요합니다.
- 응답 DOM 구조가 바뀌면 파서가 쉽게 깨질 수 있습니다.
- 대량 처리에는 속도와 사용 제한 문제가 큽니다.

### 권장 결론
- 운영 파이프라인: `API 방식` 권장
- 개발/검증용: `사용자 로그인 브라우저 기반 반자동 RPA Lab Mode`는 가능
- 현재 프로젝트에는 관리자 화면에서 `Gemini / ChatGPT` 분석 도구 선택 구조를 두고, ChatGPT는 API 키 기반으로 연결하는 구조가 안전합니다.

## 2. Playwright 기반 데이터 수집 품질 강화

이번 개선에서 Playwright가 상세 페이지 본문을 함께 수집해 `collection_evidence` 테이블에 저장하도록 구조를 추가했습니다.

저장 대상:
- 상세 페이지 제목
- 첨부파일명
- 작성일
- 공고만료일
- 상세 페이지 본문 텍스트

효과:
- PDF/HWP 파싱 실패 시에도 게시글 본문 증거를 보존할 수 있습니다.
- AI 분석 입력을 첨부파일 텍스트 + 상세 페이지 본문으로 확장할 수 있습니다.
- 추후 법원 페이지 구조 변경 감지와 관리자 검수에 활용할 수 있습니다.

## 3. RP-20260703-008 실패 원인

원본 파일:
- `울산지방법원 2025하단203 부동산 매각공고 게시 허가 신청.pdf`

진단 결과:
- PDF 6페이지
- 각 페이지 `pdfplumber` 추출 텍스트: 0자
- 각 페이지 이미지 객체: 2개
- 각 페이지 문자 객체: 0개

결론:
- 텍스트 PDF가 아니라 이미지 스캔 PDF입니다.
- 실패 원인은 AI 분석이 아니라 텍스트 추출 단계의 한계입니다.
- 앞으로는 이런 파일을 `OCR_REQUIRED`로 분류하고 OCR 엔진 연동 대상으로 처리하는 것이 적절합니다.

## 4. 회생/파산 상품성 매입/매각 기준 도구

기초 룰 기반 평가 도구를 추가했습니다.

평가 요소:
- 분석 완료 여부
- 파싱 상태
- 최저매각가격 존재 여부
- 입찰일 임박/경과 여부
- 권리/하자/주의 키워드
- 부동산/동산 구분

출력:
- 점수: 0~100
- 등급: A/B/C
- 라벨: 관심/검토/보류
- 평가 사유 목록

주의:
- 현재 점수는 의사결정 보조용입니다.
- 실제 매입/매각 판단에는 등기부, 감정평가서, 실거래가, 점유/인도 가능성, 권리관계 확인이 추가로 필요합니다.
