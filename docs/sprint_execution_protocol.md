# 스프린트 실행 프로토콜

## 목표
기획/개발 시 의미 없는 전체 코드 재검토를 줄이고, 매 스프린트를 작은 단위로 닫는다.

## 스프린트 시작 체크
1. `PROJECT_BRIEF.md` 확인
2. 최신 리포트 확인
3. 이번 작업에 직접 관련된 파일만 탐색
4. 작업 전 현재 서버/DB 상태를 짧게 확인

## 구현 순서
1. 기존 구조 확인
2. 최소 범위 구현
3. 격리 테스트 우선 실행
4. 운영 DB에 영향을 주는 테스트는 명시적으로 이유를 기록
5. 로컬 서버 렌더링 확인
6. `reports/*_report.md` 작성
7. `reports/project_build_summary_and_next_instructions.md` 갱신

## 금지/주의
- 원문 텍스트나 PII를 콘솔/감사 로그에 남기지 않는다.
- 테스트를 위해 운영 DB를 반복 오염시키지 않는다.
- 실패 job을 조용히 무시하지 않는다.
- 새 외부 의존성을 추가할 때는 설치 가능성, 실패 메시지, 대체 경로를 같이 만든다.

## 스프린트 리포트 최소 양식
```markdown
# [스프린트명] 완료 결과 리포트

## 1. 구현된 주요 기능
## 2. 보안 및 예외 처리
## 3. 테스트 결과
## 4. 다음 검토 사항
```
