# 장시간 온비드 통합 개발 목표

## 현재 목표
온비드 API 키가 준비되기 전까지 외부 연동 없이 완성도를 올릴 수 있는 기반을 선행 구축한다.

## 단계별 목표

### Step 1. API 대기 중 로컬 MVP 안정화
- 샘플 온비드 공매 데이터 수집
- 공매 목록/상세 화면
- 사건-공매 수동 연결
- 기본 환가 분석 계산
- 관리자 수집 로그 확인

상태: 완료

### Step 2. 자동 연결 후보
- 주소 정규화 기반 후보 추천
- 자산 유형 일치 점수
- 사건번호 포함 점수
- 후보 저장/확정 연결 흐름

상태: 완료

### Step 3. 관리자 화면 목적별 분리
- `/admin/assets`: 물건/OCR/공매 개요
- `/admin/analysis`: 분석/워커/모델 결과 개요
- `/admin/reviews`: 검수/감사 로그
- `/admin/collection`: 수집/온비드 동기화

상태: 1차 완료

### Step 4. API 키 수령 후 실제 온비드 연동
- `ONBID_API_KEY` `.env` 반영
- 실제 목록 엔드포인트 매핑
- 상세/공고/결과 엔드포인트 매핑
- 실패 재시도 및 원문 JSON 저장 검증

상태: 대기

### Step 5. 다음 구현 후보
- 사건 상세 화면에 `공매 연결` 탭 추가
- 연결 상태 변경 UI: 후보, 확인중, 연결완료, 연결제외, 매각완료, 환가포기
- 입찰마감 D-7/D-3/D-1 알림 테이블 및 배치
- 실패한 온비드 수집만 재시도하는 큐
- API 키 수령 후 실제 스펙 문서 기준 클라이언트 교체

상태: 다음 스프린트 추천

## API 키 수령 시 필요한 값
- `ONBID_API_KEY`
- 사용 가능한 실제 API 상품명 또는 엔드포인트 문서
- 일 호출 제한/분당 제한
- 응답 포맷 예시 JSON
- 운영/개발 키 구분 여부
