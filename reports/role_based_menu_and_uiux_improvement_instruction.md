# 사용자/관리자 메뉴 구조 및 UI/UX 개선 지시서

작성일: 2026-07-05

## 1. 목적

현재 화면은 경매 물건, 분석 상태, 리스크, 작업 상태가 한 화면에 많이 노출되어 사용자가 핵심 판단을 하기 어렵다.

이번 단계의 목적은 사용자와 관리자의 역할을 분리하고, 메뉴 구조를 정리해서 화면 피로도를 줄이는 것이다.

핵심 방향:

- 사용자에게는 물건 검토에 필요한 메뉴만 보여준다.
- 관리자 메뉴는 사용자에게 보이지 않게 한다.
- 관리자 화면은 사이트 관리, 물건 관리, 사용자 관리, 분석 관리로 나눈다.
- 첫 화면에는 요약과 우선순위만 보여주고 세부 정보는 하위 화면으로 보낸다.

## 2. 사용자 메뉴 구조

### 2.1 사용자에게 보일 메뉴

사용자 메뉴는 단순하게 시작한다.

```text
물건 찾기
관심/지켜보기
패스한 물건
내 설정
```

권장 1차 메뉴:

```text
물건 찾기
  분석 완료 또는 추천 우선 물건 목록

내 물건
  관심물건
  지켜보기
  패스한 물건

내 설정
  로그아웃
  표시 옵션
```

`관심물건`, `지켜보기`, `패스`는 같은 카테고리로 묶는다.

권장 이름:

```text
내 물건
```

하위 탭:

```text
관심
지켜보기
패스
```

### 2.2 사용자에게 숨길 메뉴

사용자 화면에서는 아래 메뉴를 보이지 않게 한다.

```text
관리자
분석 작업
워커 상태
수집 상태
모델 비교 상세
DB 관리
사용자 관리
로그/이벤트
```

단, 관리자 권한 사용자가 로그인했을 때는 별도 관리자 진입 버튼을 표시할 수 있다.

### 2.3 사용자 홈 화면

사용자 첫 화면은 “경매 물건을 훑는 화면”이어야 한다.

첫 화면 우선순위:

```text
1. 볼 만한 물건
2. 분석 완료 물건
3. 마감이 가까운 물건
4. 신규 등록 물건
```

초기 화면 구성:

```text
상단:
  검색
  간단 필터
  내 물건 메뉴

본문:
  물건 카드 목록

카드:
  사건번호
  제목
  지역/주소 요약
  최저가
  일정
  핵심 리스크 한 줄
  추천/주의 배지
  관심
  지켜보기
  패스
  상세
```

## 3. 사용자 물건 분류

로그인 사용자의 물건 분류는 `user_event_actions`로 관리한다.

권장 action:

```text
BOOKMARKED
WATCHING
PASSED
```

의미:

```text
BOOKMARKED
  관심물건
  적극적으로 다시 볼 물건

WATCHING
  지켜보기
  아직 판단 전이지만 추적할 물건

PASSED
  패스
  기본 목록에서 숨길 물건
```

정렬/조회 원칙:

```text
물건 찾기:
  PASSED 제외

내 물건 > 관심:
  BOOKMARKED만 표시

내 물건 > 지켜보기:
  WATCHING만 표시

내 물건 > 패스:
  PASSED만 표시
```

한 물건에 여러 action이 생기지 않도록 한다.

권장 규칙:

```text
관심 클릭 -> 기존 WATCHING/PASSED 제거 후 BOOKMARKED 저장
지켜보기 클릭 -> 기존 BOOKMARKED/PASSED 제거 후 WATCHING 저장
패스 클릭 -> 기존 BOOKMARKED/WATCHING 제거 후 PASSED 저장
해제 클릭 -> 해당 action 삭제
```

## 4. 관리자 메뉴 구조

관리자 화면은 하나의 큰 대시보드가 아니라 역할별 메뉴로 나눈다.

권장 관리자 메뉴:

```text
대시보드
물건 관리
분석 관리
수집 관리
사용자 관리
사이트 관리
리뷰/품질
```

### 4.1 대시보드

첫 화면은 요약만 보여준다.

표시 항목:

```text
전체 물건 수
분석 완료 수
분석 대기 수
분석 실패 수
오늘 수집 수
OCR 필요 수
UNKNOWN 날짜 수
LOCAL_INGESTED 수
활성 사용자 수
워커 상태
```

첫 화면에서 너무 긴 물건 리스크 목록은 제거한다.

대시보드에는 “문제 요약”만 보여준다.

```text
실패 job 3건
UNKNOWN 날짜 12건
OCR 필요 5건
오래 멈춘 작업 1건
```

각 항목을 클릭하면 해당 관리 화면으로 이동한다.

### 4.2 물건 관리

목적:

```text
수집된 경매 물건과 분석 상태를 관리한다.
```

기능:

```text
물건 목록
상태 필터
분석 완료/미완료 필터
리스크 등급 필터
등록일/마감일 필터
원본 파일 열기
메타데이터 수정
강제 숨김 또는 보류
```

물건 리스크의 상세 상태는 이 화면으로 이동한다. 관리자 대시보드 첫 화면에 전부 노출하지 않는다.

### 4.3 분석 관리

목적:

```text
AI 분석 작업과 결과를 관리한다.
```

기능:

```text
분석 job 목록
대기/진행/성공/실패 필터
worker 상태
재시도
취소 요청
강제 재분석
Gemini 결과 보기
ChatGPT/Codex 결과 보기
분석 이벤트 로그
```

사용자 화면에서 제거한 모델 비교와 작업 로그는 분석 관리에 둔다.

### 4.4 수집 관리

목적:

```text
법원 공고 수집과 파일 품질을 관리한다.
```

기능:

```text
수집 실행 이력
2026-06-15 이후 수집 상태
다운로드 성공/실패
중복 파일
UNKNOWN 날짜 항목
LOCAL_INGESTED 항목
OCR 필요 문서
HWP 변환 필요 문서
```

### 4.5 사용자 관리

목적:

```text
로그인 사용자와 사용자별 물건 분류를 관리한다.
```

기능:

```text
사용자 목록
활성/비활성
역할 변경
사용자별 관심/지켜보기/패스 개수
사용자별 숨김 물건 확인
비밀번호 초기화
```

### 4.6 사이트 관리

목적:

```text
서비스 운영 설정을 관리한다.
```

기능:

```text
기본 분석 provider
페이지당 표시 개수
사용자 화면 노출 옵션
로그 보존 설정
백업 상태
포트/실행 명령 안내
```

### 4.7 리뷰/품질

목적:

```text
분석 결과 품질을 검수하고 모델/프롬프트 개선에 활용한다.
```

기능:

```text
관리자 리뷰 입력
분석 결과 점수
가격 정확도
날짜 정확도
위험 판단 정확도
근거 충분성
환각 의심 여부
모델별 품질 비교
```

## 5. UI/UX 개선 원칙

### 5.1 정보 밀도 낮추기

사용자 화면은 카드당 표시 정보를 줄인다.

기본 카드에 길게 표시하지 않을 것:

```text
전체 분석 전문
작업 로그
모델 비교 전문
원문 전체
반복되는 물건 설명
리스크 세부 항목 전체
```

대신 한 줄 요약을 사용한다.

예:

```text
권리 확인 필요
가격 확인 필요
명도 리스크 가능
일정 임박
분석 완료
```

### 5.2 행동 중심 버튼

사용자 카드 버튼은 판단 행동 중심으로 둔다.

권장 버튼:

```text
관심
지켜보기
패스
상세
원문
```

분석 요청 버튼은 사용자에게 계속 노출하기보다, 분석 미완료 물건에만 작게 표시한다.

### 5.3 관리자 화면의 정보 분산

관리자 첫 화면은 모든 데이터를 보여주지 않는다.

첫 화면:

```text
요약 카드
문제 알림
바로가기
최근 실패 몇 건
```

상세 정보:

```text
물건 관리
분석 관리
수집 관리
사용자 관리
리뷰/품질
```

### 5.4 메뉴 표시 규칙

권한별 메뉴:

```text
비로그인:
  로그인

일반 사용자:
  물건 찾기
  내 물건
  내 설정

관리자:
  사용자 메뉴
  관리자 메뉴
```

관리자 권한이 없으면 관리자 메뉴를 렌더링하지 않는다.

## 6. 개발 순서

### Loop 1. 메뉴 구조 설계 및 라우트 준비

작업:

- 사용자 메뉴 구조 정의
- 관리자 메뉴 구조 정의
- route 이름 정리
- 기존 `/user`, `/admin` 유지
- 새 화면 URL 설계

권장 URL:

```text
/user
/user/bookmarks
/user/watchlist
/user/passed
/user/settings

/admin
/admin/assets
/admin/analysis
/admin/collection
/admin/users
/admin/settings
/admin/reviews
```

완료 기준:

- 기존 URL은 깨지지 않는다.
- 새 메뉴 구조가 템플릿에 반영된다.

### Loop 2. 사용자 메뉴와 내 물건 카테고리

작업:

- `관심/지켜보기/패스`를 `내 물건` 카테고리로 묶기
- 사용자별 action 상태 배지
- 각 탭별 목록 조회
- 패스한 물건은 기본 `/user`에서 제외

완료 기준:

- 일반 사용자는 관리자 메뉴를 보지 않는다.
- 내 물건에서 관심/지켜보기/패스를 전환할 수 있다.

### Loop 3. 사용자 카드 정보 축소

작업:

- 카드 표시 정보 줄이기
- 반복 요약 제거
- 긴 분석 결과 접기
- 모델 비교 기본 노출 제거
- 작업 로그 제거
- 모바일 카드 높이 줄이기

완료 기준:

- 한 화면에서 더 많은 물건을 피로 없이 훑을 수 있다.
- 상세 정보는 필요할 때만 열린다.

### Loop 4. 관리자 메뉴 분리

작업:

- 관리자 대시보드 요약화
- 물건 관리 화면 분리
- 분석 관리 화면 분리
- 수집 관리 화면 분리
- 사용자 관리 화면 분리
- 사이트 관리 화면 분리
- 리뷰/품질 화면 분리

완료 기준:

- 관리자 첫 화면에서 리스크 상태정보가 과도하게 나오지 않는다.
- 문제 요약을 클릭하면 상세 관리 화면으로 이동한다.

### Loop 5. 권한 기반 메뉴 표시

작업:

- 로그인 사용자 role 확인
- 일반 사용자에게 관리자 메뉴 숨김
- 관리자에게 관리자 메뉴 표시
- route 접근 권한 검사

완료 기준:

- 일반 사용자가 `/admin`에 직접 접근해도 차단된다.
- 관리자만 관리자 메뉴를 볼 수 있다.

## 7. 화면별 목표 요약

사용자:

```text
많이 읽지 않고 빠르게 고른다.
관심/지켜보기/패스로 정리한다.
관리자용 상태 정보는 보지 않는다.
```

관리자:

```text
사이트 상태를 요약으로 본다.
문제가 있는 영역으로 이동한다.
물건/분석/수집/사용자/설정을 따로 관리한다.
```

## 8. 검증 체크리스트

```text
비로그인 상태에서 사용자 화면 접근 처리
일반 사용자 로그인 시 관리자 메뉴 숨김
관리자 로그인 시 관리자 메뉴 표시
관심/지켜보기/패스 탭 동작
패스한 물건 기본 목록 제외
관리자 대시보드 요약 표시
관리자 상세 메뉴 이동
모바일 화면에서 메뉴와 카드가 겹치지 않음
```

## 9. 중요한 결정

사용자 화면과 관리자 화면은 같은 데이터를 보더라도 목적이 다르다.

```text
사용자 화면:
  선택과 검토를 돕는 화면

관리자 화면:
  운영과 품질 관리를 돕는 화면
```

따라서 사용자 화면에서 정보를 줄이는 것은 기능 축소가 아니라 서비스화를 위한 정리다.  
자세한 리스크, 분석 작업, 모델 비교, 오류 상태는 관리자 화면으로 보내고, 사용자는 물건을 빠르게 분류할 수 있게 만든다.
